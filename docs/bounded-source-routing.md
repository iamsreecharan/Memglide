# Bounded source routing v4

V4 is an explicit experiment in the existing local source engine, not a new
coding model. The known-path source preparer, v1/v2/v3 compatibility policies,
default policy and explicit memory remain available. No model or embedding call
is used for discovery, ranking, screening or verification.

```sh
uv run memglide-codex --discover --selection-policy v4 --project PROJECT_ID \
  'Correct the cooling window calculation for flow rate and capacity.' -- --json
```

The flow is **approved repository → secure index refresh → scoped lexical
retrieval → conservative current-source screen → existing syntax ranking →
bounded complete-source bundle → final source/policy verification → native
agent**. Insufficient evidence returns the exact original task. Agents remain
free to investigate and run tests; the router does not claim they avoided work.

The extension addresses four independently diagnosed stage boundaries:

- Supported production scope is applied before lexical/symbol/FTS output caps.
  Normal public search and earlier policies retain their original scope.
- Only exhaustive, known nonproduction parse diagnostics may be exempted from
  the global index-health guard. Their exact indexed/current hashes and ignore
  policies are checked. Relevant production errors, unknown/read/scan failures,
  partial indexes, truncated diagnostics and policy changes still decline.
- A separate coarse phase reads at most 100 current bodies, including exempt
  parse-warning files, with a cumulative 2 MiB budget. It removes candidates
  only when a conservative lexical upper bound cannot meet the later rule.
  Comments, literals, Unicode normalization and uncertain explicit anchors
  remain safe false positives. They cannot justify final source selection.
- Unsupported production files remain an observed frontier. Potential evidence
  causes fallback; a low existing search score is not proof of irrelevance.

At most 24 potentially sufficient supported files then enter the unchanged v3
syntax worker, with its existing separate 2 MiB input, node/output/time bounds.
The coarse and syntax budgets are distinct. Final verification and source
delivery reread files, so neither limit is a whole-operation read/latency/RSS cap.
Every inspected coarse competitor, including rejected and exempt files, retains
current-version and ignore-policy checks until delivery. More than 24 possible
competitors, ambiguity or any failed safety check produces original-task fallback.
Selected files and bounded direct production helpers are delivered completely.

The private `coarse_selection` receipt records bounded file/byte counts, parse
exceptions, possible unsupported evidence, a sampled hash frontier, phase time
and whether that bounded scope completed. It contains no source bodies or
extra model-visible instructions. `scope_complete` describes this bounded
retrieval phase; it does not establish global or semantic dependency completeness.
The launcher validates this receipt and the complete-source envelope before
native handoff. Automatic warm-memory injection remains disabled.

The original [v3 assessment](../benchmarks/router-v3-assessment.md), source
snapshots, tasks and outcomes are preserved. Development regressions and reviewer
counterexamples are not fresh evaluation tasks. The new
[offline protocol](../benchmarks/automatic-v4-protocol.md) freezes policy and
runners before independent corpus authoring. Its scope-inclusion outcomes do
not establish coding correctness or token savings. A separate
[native protocol](../benchmarks/router-coding-protocol.md) compares bare Codex,
oracle-known-path source delivery and v4 on new path-free coding tasks, with
independent grading and all failed attempts in cost-per-success accounting.

V4 remains opt-in. No default promotion, new model-cost improvement or hosted
production-readiness claim follows from correct screening or passing local tests.

The [fresh v4 assessment](../benchmarks/router-v4-assessment.md) records a failed
selection gate: zero complete positive scopes in 24 v4 observations, equal to v3,
versus six known-path observations. V4 added about 85 ms mean local preparation
time relative to v3. Nine of twelve declared whole-source bundles exceed the
frozen 12,000-byte envelope cap; the three feasible bundles also failed automatic
delivery. These are source-inclusion and local-overhead findings, not measured
coding success, full coding-task latency, tokens or model charges. Keep the
original outcomes; any revised policy needs separate development cases and a new
held-out corpus. The candidate did not qualify for the matched coding study.
