# Known limitations

- **Static evidence is incomplete.** Python AST and Tree-sitter cover Python, JS, TS, and TSX structure. External packages, dynamic imports, reflection, runtime dependency injection, and ambiguous calls can stay unresolved. Other supported text files receive filename/text search without structural claims.
- **Parser failures are visible gaps.** Native JS/TS parsing runs in an isolated worker with a timeout. A grammar error, worker fault, or resource-limit failure can leave a file available only to filename/text search. Inspect the project's indexing report and passport warnings rather than assuming every supported-language file has structural evidence.
- **Passports describe evidence.** Current hashes mean the returned source matched its version at validation time. They do not prove task sufficiency, semantic correctness, or that no file changed immediately afterward. Review warnings, expand context, and run appropriate application tests.
- **Ranking and packing can miss available bodies.** Lexical overlap can favor documentation or unrelated modules, and breadth can exhaust the response budget before all resolved helper implementations fit. A recognized task role enables focused level-2 selection; inspection queries without a recognized role bypass that cap. Neither path guarantees complete source. The [refinement assessment](https://github.com/iamsreecharan/Memglide/blob/8acc8af/benchmarks/refinements.md) retains the first unseen misses and explicitly labels subsequent validation reuse. Further quality work needs a newly authored independent evaluation.
- **Tokens are estimated.** The deterministic estimator uses serialized application-JSON UTF-8 bytes, including metadata, but excludes HTTP/MCP protocol framing and the client's other model context. It is not the client's tokenizer or billing meter. Output-size comparisons establish no percentage cost or total-token saving.
- **Memory is explicit.** Agents must submit findings. Memglide cannot read hidden model reasoning, capture unsent thoughts, or remove/rewrite Codex conversation history. Unreferenced claims remain subject to inspection; stale source-linked memories do not become current simply because their text is edited.
- **Sessions are temporary.** The default inactivity limit is 60 minutes with an eight-hour absolute cap. Status and session lists do not extend it. Explicit retrieval/recall and memory activity may refresh inactivity but never exceed the session's absolute deadline. Runtime cleanup can lag the deadline until the next maintenance/access/cleanup operation; access rejects expired sessions immediately. Persistent repository indexes have a separate lifetime.
- **Local trust is required.** V1 has no multi-user authentication, database encryption, public network deployment, or forensic deletion guarantee. Keep the API on loopback and its state private. Sensitive-content detection is heuristic. An MCP client can retrieve eligible source in registered roots.
- **Watchers require a running owner.** Manual reindex covers offline changes. Filesystem watching and Git transitions can temporarily outpace background indexing; source hashes prevent blindly trusting an old snippet.
- **Indexing is bounded.** Each project scan stops at 20,000 eligible files or 100 MiB of eligible source, with a partial-index error in its report. The default per-file limit is 512,000 bytes and can be changed in Settings. Narrow `.memglideignore` or ignored directories for a large repository; a Git subdirectory cannot be registered as a separate root.
- **Platform coverage is observed separately.** Installation commands include macOS, Linux, Windows, and WSL, but only environments recorded in [historical verification log](archive/PROGRESS.md) have been executed here. Windows ACL behavior, remote filesystems, and very large monorepos need separate validation.
- **No cloud or embeddings in V1.** No Memglide-owned service receives repository contents. Connecting an external agent is a separate trust decision. Adaptive ranking, local embeddings, and complete agent-usage benchmarks belong to the proposed V2, not this release's claims.

See [historical verification log](archive/PROGRESS.md) for concrete remaining verification issues. These limits should guide use even when all local checks pass.
