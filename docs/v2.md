# V2 evaluation proposal — plan only

V1 remains independent of this work. No embeddings, benchmark agent, external model API, adaptive budget policy, or multi-agent orchestration is required to run V1.

## Controlled coding-task comparison

Create a versioned task corpus with fixed repository commits, deterministic environment setup, explicit task instructions, and independent outcome checks. Include authentication/debugging tasks, cross-module refactors, frontend changes, large-file navigation, unresolved/dynamic dependencies, and stale-memory hazards. Separate a tuning set from a held-out evaluation set.

For each task compare standard Codex with Codex plus Memglide using the same model, model settings, tool permissions, environment, starting commit, and time/usage limits. Randomize order and repeat tasks to capture variance. Record failures and retries rather than discarding inconvenient runs. Keep benchmark source/results local unless their publication is explicitly authorized.

Collect actual client-reported input, output, cached-input, and total billed usage across the complete run, including failed attempts, expansions, and any planning turns. Record provider/model/pricing versions if converting usage into cost. A retrieval response's estimated size is auxiliary data, not a replacement for the client usage record.

Report task success, test outcomes, time to completion, total cost, cost per successful task, retrieval precision/recall against independently labeled evidence, stale-evidence rates, and unresolved-dependency handling. Pair per-task results and include uncertainty and failure cases. Do not claim savings without comparable complete-run measurements and task-quality controls.

## Optional retrieval extensions

An evaluation adapter can record retrieval candidates, scoring reasons, expansions, passports, source versions, and task outcomes without copying hidden model reasoning. A local experiment store can join these records to client usage IDs and exact benchmark commits. Source/secret exclusions and deletion controls must remain intact.

Evaluate ranking changes and adaptive context budgets as isolated features. Only add optional local embeddings or FAISS if they improve measured outcomes enough to justify memory, startup, indexing, and maintenance costs. The deterministic V1 path should remain available as a baseline and fallback. Multi-agent integration would require explicit session ownership, provenance, stale-evidence rules, and a separate security review before implementation.
