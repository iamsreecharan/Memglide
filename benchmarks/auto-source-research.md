# Automatic source discovery: research and implementation hypotheses

Research date: **19 October 2026**. This review supports an opt-in, local task-to-source adapter over Memglide's existing index. It does not establish that the new adapter is cheaper, faster, more accurate or better than every other architecture. No model requests were made for this research. The [JSON ledger](auto-source-research.json) records all 15 requests, 12 successful responses, three failed URLs, downloaded-byte hashes and exact reading scopes. HTTPS used the inherited proxy and certificate verification; no credentials or network policy were changed.

## Start with the capabilities already present

Production `Indexer._search` already combines project-local document frequencies, normalized identifiers and prose, exact symbol/path matches, signature/path evidence, FTS5 BM25, source-role weights, deterministic tie-breaking and explanations. Caller-intent queries can use resolved graph edges. The context engine already bounds direct source, dependencies and graph metadata. The explicit-path source-only adapter already provides complete files after checking approval, indexing, safe paths, live ignore policies and current source versions. These mechanisms should be reused and preserved.

The missing product seam is automatic, conservative selection of files from a natural-language task followed by the existing secure complete-file preparer. A new vector service, a second rank-fusion engine or a model-based retrieval planner would duplicate substantial existing functionality and add costs that have no demonstrated benefit here. Existing metadata retrieval also enumerates project symbol/file rows: reusing it does not automatically provide bounded preparation on a large or adversarial index. The new adapter needs explicit query, row, value, deadline and output limits, with honest fallback when its selection evidence is incomplete.

## The smallest promising extension

The proposed strategy is a **bounded source-selection and verification step**, with no auxiliary inference:

1. Keep zero-state-access bypasses for off mode, an explicit supplied-context assertion and missing authorization inputs. Natural-language ambiguity is not an excuse to guess that a task is understood.
2. Generate a bounded candidate set from the existing index. Combine direct lexical/symbol/path evidence deterministically, group declarations by file, explain matches privately and reject insufficient or ambiguous evidence. Reuse local project scopes; do not query other approved repositories implicitly.
3. Select unique complete production files under a shared context budget. Permit only bounded resolved local helper relationships when useful and affordable. Leave broader exploration available to the coding agent. A `FULL SOURCE` decision should mean complete selected files, never an entire repository and never proven global completeness.
4. Suppress an already-selected path or source actually present in the current caller input. An old source hash, old receipt or thread ID does not prove that source is still in Codex context after compaction. Any retained-context assertion must be explicit and documented.
5. Pass selected files through current approval, ignore, secure-path, size and live-source verification. Do not silently clip a required body, trust stale AST offsets or treat a source hash as semantic truth. On failure, preserve the original task exactly and record why.
6. Keep ranking, decision, source versions, retrieval/verification/preparation timing, added bytes and token estimates in private reports. Model tokens, pricing equivalence and actual bills require separate observed native/provider telemetry. No comparator means no measured avoided work.

The feature is new as a Memglide product integration, not a claim to invent sparse retrieval, graph ranking or selective RAG. Its potential benefit is replacing manual target-path selection and some subsequent investigation while avoiding low-evidence injection. Its potential regression is spending local discovery work on tasks where bare Codex would proceed quickly. Both must be tested.

Experimental symbol-level excerpts can later be compared independently. They must be labeled partial evidence, retain source version/ranges, and never silently replace complete code needed to understand imports, module state, enclosing declarations or helper behavior. Tree-sitter/AST structure does not prove semantic dependency closure.

## What stays out of the default path

Automatic warm-memory injection remains disabled; preserve the optional memory implementation. Do not add an embedding service, learned selector, iterative generation loop, full-repository PageRank map, model-based summary compressor or extra discovery MCP interaction without measured benefit. Do not manufacture provider cache boundaries or move untrusted source into privileged instructions.

The prior 80-completed-run study remains descriptive historical evidence. Its matched source-only comparison supplied known source paths; it does not prove that automatic selection works or transfers its cost/time estimates. Its warm-memory regression argues for keeping memory optional, not deleting it or concealing its failed comparison. Preserve historical reports and raw attempts unchanged.

## Evaluation needed before promotion

First run inexpensive offline tests for file-selection coverage, abstention, duplicate suppression, preparation overhead and source freshness. Include changed/deleted files, stale index rows, ignores, secrets, nested/symlink escapes, large files, unsupported/incomplete evidence, ambiguous tasks and multi-file dependencies. Keep uncertainty and incomplete selection visible.

Preregister the model comparison separately: A bare Codex; B existing explicit known-path source preload; C opt-in automatic discovery with no manually supplied target paths. Freeze code, tasks, grading, model/settings and cost assumptions before formal requests. Use fresh held-out tasks and unfamiliar repositories, balanced arm order, repeats, isolated starts, independent protected grading, equivalent cache conditions where controllable, and every failure/interruption retained. Hidden tests, reference fixes and target-path labels must never be indexed into C's repository or selector inputs.

Measure whole-task time including context preparation, observed input/cached/uncached/output tokens, cost per strict success, paired means/medians, variability and uncertainty. Separate selection/body bytes from measured tokens; local time from native/server time; API-price equivalents from actual billed charges; recognized read commands from filesystem reads. Reject correctness or security regressions. Large paid model comparisons require the user's approval of a concrete estimated maximum budget; none was started by this research.

## Follow-up: should a task router add one specific memory rule?

**Keep automatic warm-memory injection disabled.** A router that selects a rule only when it is useful and absent from current source is a reasonable hypothesis, but the existing local data cannot prove those semantic conditions. This follow-up reviewed production memory, context-passport and explicit memory-preparation code; it added no application code or model request.

`MemoryEngine.save_memory` validates category, bounded nonempty content/provenance, detected-secret exclusions and current cited source versions. The `verified_fix` category is supplied by the caller; its name is not a verification result. `_fingerprint` deduplicates a category, whitespace-normalized content and source versions. `version` identifies exact content/provenance/source references. `_memory_view` checks cited source freshness and otherwise reports “Requires inspection.” None proves that a claim follows from source, adds new information or helps the next task.

The existing context memory selector already uses task/query lexical overlap, current-source status, category and prior-attempt intent. This is task-aware ranking, not a prediction of saved work. The explicit `prepare_memory_prompt` adapter bounds caller-selected IDs, current-session lifecycle, ownership, current ignores, source hashes, exact claim versions and added bytes; its notice explicitly states that hashes do not verify meaning. The new automatic source adapter keeps this memory operation separate and disabled.

A critical passport distinction matters for deduplication: `ContextEngine._build_passport` merges actual source-item hashes **and selected memory source references** into `selected_files` and `verified_source_hashes`. A path in that passport does not establish that the whole file body reached the model. Check the actual delivered source envelope/items and source ranges. Existing `known_memory_versions` can omit the exact claim version explicitly acknowledged by the caller; an ID alone does not identify what a client has seen, and a historical acknowledgement does not prove native context survived compaction.

Current local checks can establish ownership/lifecycle, unchanged cited bytes, exact claim identity and literal duplication against actually delivered text. They cannot establish semantic truth, semantic novelty from nonmatching wording, usefulness or a favorable token/latency tradeoff. A paraphrase can add no information while failing exact-text deduplication; a false caller claim can cite unchanged source and still be wrong. A source-backed memory whose cited full source is already delivered may still highlight useful information, but that is an efficacy hypothesis requiring comparison, not a reason to inject it automatically.

### Fresh official latency guidance

The [official OpenAI latency guide](https://developers.openai.com/api/docs/guides/latency-optimization) was fetched again successfully through normal HTTPS/proxy handling. This review read its seven-principles introduction and selected full sections on generating fewer output tokens, reducing input, making fewer requests and using classical computation when an LLM is unnecessary. The exact response was 490,457 bytes, SHA-256 `8b0419270ef58348716b7b451cb80bba8b1efc86118b6c5d141a31f3d18bb0a9`; the JSON ledger preserves retrieval time, URL, response status and reading scope.

The guide separates the cost of processing input from output generation and sequential request roundtrips. Its numerical shortening/speed examples are broad heuristics, **not Memglide predictions or measured gains**. Reducing ordinary input can improve price-equivalent cost without a proportional latency improvement. Source or memory injection must remove enough investigation or repeated interactions to offset its selection, verification and additional input. An extra LLM router would itself add a request, contrary to this implementation's zero-auxiliary-inference constraint. The guide's generic shared-prefix advice also does not change the native CLI's independently documented cache-boundary limitations.

### A precise next experiment

Start with an **offline shadow audit**, with no memory injection and no model calls. For each task, record at most one candidate rule, its ownership/freshness, lexical relationship, literal duplication against actual delivered source, added bytes and selection overhead. Include paraphrased duplicates, unrelated Current claims, misleading `verified_fix` labels, source/ignore changes, ended/expired sessions and passports containing reference paths without delivered bodies. Keep independent semantic labels outside all discovery inputs; report false positives and abstentions. This tests safe routing mechanics and finds failure cases; it cannot prove coding-agent savings.

If that audit is promising, preregister a separate pilot for **four fresh related two-task sequences**, at least two Python and two TypeScript repositories, source-only versus the identical source policy plus at most one caller-verified finding, two repeats and balanced order: **32 original assignments**. Produce prior findings before any hidden grading; no future reference fix or hidden correctness result may select a finding. Include capture, verification, selection and every failed/fallback attempt in whole-sequence cost, alongside follow-up-only effects. Reuse only the same still-active Memglide session across native processes. Grade independently; retain the source-only arm, preserve correctness/security and report paired mean/median effects with uncertainty.

Using only the same historical three-times-observed-maximum planning method, 80 prior completed assignments supply a maximum possible-write price equivalent of $0.0860593; three times this is $0.2581779 per proposed assignment, or a rounded **$8.27 planning high for 32 assignments**. This is not an invoice, guaranteed maximum or hard cap. Prices and model availability require rechecking before approval; unfamiliar work can exceed the scenario. This is a proposed future experiment, **not authorized or executed**. Keep the current frozen source-only formal comparison unchanged rather than adding an untested memory treatment after preregistration.
