## Architecture decision

For an ordinary task, the first candidate should be **a conservative local preflight followed by unchanged native Codex execution**. The preflight either passes the task through unchanged or appends a small, versioned source bundle before the first model request. It must not call another model to decide whether retrieval is useful, launch an MCP server on a skip, or perform a mandatory model-driven final freshness check.

This is a hypothesis addressing the observed extra interaction and over-expansion. It is not a claim that Memglide can inspect Codex's hidden understanding or remove context already inside a native Codex session. Explicit paths, identifiers and a supplied manifest of already delivered source are observable routing signals; “the model has sufficient understanding” is not.

### Proposed ordinary-task path

1. **Route using local evidence only.** Inspect the task's explicit path/symbol hints and, when available, hashes of context already delivered. Record a deterministic decision and reason. Skip augmentation for unsupported, unsafe, ambiguous or already covered inputs instead of performing broad speculative expansion. A false skip can still force Codex to search; measure that outcome.
2. **Select before reading broadly.** Prefer exact project-relative paths and definitions. Add only necessary direct local helpers under a shared file/byte cap. The dependency limit must constrain dependency expansion as well as primary hits. Deduplicate paths and contained spans. Stop or abstain when the limit would require cutting a necessary definition in half.
3. **Read securely and deliver upfront.** Reuse Memglide's approved-project and verified-source guards. Include relative path, source identity and complete retained source. Describe omissions explicitly. Mark repository content as untrusted evidence. Do not insert it into the instruction hierarchy or interpret its instructions as authoritative. A wrapper cannot make prompt injection impossible; native agent policies still apply.
4. **Keep the provider prefix stable.** Use stable routing/format instructions and source ordering. Avoid random retrieval IDs, wall-clock timestamps and diagnostic dumps in reusable prompt material. Append variable task/source data where the native client permits. Do not pad prompts to reach a cache threshold.
5. **Leave native tools available.** Codex may inspect additional source and run tests. Do not force it to trust an incomplete bundle, ban necessary reads, or skip validation in pursuit of a token target. This candidate deliberately avoids a required first MCP interaction; MCP remains a separate supported integration rather than an automatic additional stage in every ordinary task.
6. **Measure the full path.** Count preparation wall time and CPU before the native request, actual native input/cached/output usage, commands/tool events, success and failures. Record what was routed, bundled, skipped or omitted. Byte limits are engineering limits, not measured model-token counts.

Exact routing thresholds and source caps should be selected using development fixtures, then frozen before viewing the new tasks' live outcomes. Related work motivates these choices; it does not determine an optimal threshold for this workload.

## What should stay out of this iteration's default path

- **An LLM “should I retrieve?” classifier:** it pays for another model decision before the task begins. Use deterministic abstention and measure its mistakes.
- **A new summarizer or memory extraction model:** its total lifecycle cost must be justified by repeated work; it should not silently run for unrelated short tasks.
- **Large embedding/reranking dependencies or a persistent watcher merely for fashion:** the previous experiment's approximately 0.21-second indexing mean does not explain the whole slowdown. Target the extra interaction and unnecessary delivered content first.
- **Transitive dependency closure, full debug graphs or every prior note:** source selection needs a real total cap, even when the first result appears small.
- **An invented prompt-cache or context-clearing API:** expose only supported native Codex settings. Keep provider cache uncertainty visible.

These exclusions apply to the experimental common path, not a blanket deletion of existing supported features. A feature should be removed from that path when it adds measured work without benefit; broader removal requires compatibility and outcome evidence.

## Acceptance and reporting rules

The held-out experiment should compare standard native Codex with the same model/settings plus the frozen preflight. Both arms receive identical task requirements, source starting commits, testing environments and grader behavior. The source bundle is the declared treatment. Report matched pairs alongside every assigned/attempted run; a skipped augmentation is still a B run and cannot be relabeled as an A success. Show routed-versus-skipped strata and false/missed retrieval cases so apparent gains from doing nothing are visible.

Include cold preparation and warm local-state results only under explicitly separate protocols. Isolated worktrees do not reset the provider's caches or the host's filesystem cache. Counterbalance run order, capture available cached-token counts and avoid claiming equivalent provider cache state can be guaranteed. A 20-task result on purpose-built fixtures is a development benchmark, not proof of a universal improvement on large production repositories or long-term memory.

For a useful first result, task success must be preserved and the total preparation-plus-native time and native usage should improve on the relevant cohort. Report individual runs, means, medians, failures and uncertainty; speed alone cannot justify more failures. Cost per success needs reliable applicable costs for all attempted runs, including failures. Under ChatGPT device authentication with no billing telemetry, actual dollars and actual dollars per success remain **null**. Any illustrative pricing calculation must be separately labeled and must not become an “actual savings” claim.
