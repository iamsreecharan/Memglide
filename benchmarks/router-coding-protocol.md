# Fresh path-free automatic-source coding protocol

This is a new study; previous studies and offline scope observations are not
coding-agent outcomes. Importing the runner, preparing source and planning dispatch
make no model request. Native execution uses `--execute` and an accounted runtime
preflight receipt. The user has authorized the experiment; this switch prevents
accidental dispatch while engineering or auditing the harness.

The intended formal cohort contains twelve independently authored fresh coding
tasks, six Python and six TypeScript, from at least six unrelated pinned upstream
roots. Two repeats give 72 original assignments. A deliberately smaller cohort or
one repeat is labelled a pilot. The corpus author, rather than this runner's
author, supplies behavioral contracts, baseline-fail/reference-pass evidence and
external oracles after the selector/protocol freeze. No old task is relabelled
fresh. Source snapshots retain licenses and pinned-archive/file-hash provenance.

All three arms receive the exact same path-free common prompt. Public task objects
contain only opaque task/repository IDs, language and request. Private known paths,
reference patches, tests, grader arguments and expected behavior never enter A/C
preparation requests or indexed/agent repositories. B alone receives privileged
oracle-known paths to the existing compact-prefix complete-file preparation API;
this privilege must appear prominently in reports. A is bare native Codex. C uses
the explicit opt-in v4 production automatic API with the natural-language prompt
alone. Complete source and exact passthrough are the only allowed deliveries;
excerpts, automatic memory, model-assisted selection and configured MCP are absent.

The model is exactly `gpt-6.1-sol`, reasoning `low`, native `codex-cli 0.159.2`,
requested `service_tier="default"`. All arms use the same supported `exec --json`,
`--output-schema`, ephemeral state, ignored user configuration/rules, disabled
apps/web search, empty MCP map, workspace-write sandbox and never approval policy.
The inherited authentication/runtime guards remain intact. A fresh writable
`CODEX_HOME` references an existing auth binding by symlink without reading,
copying or printing credential contents. No interactive login is initiated.

Task blocks are shuffled with the recorded seed. Their six possible A/B/C orders
are cycled, yielding equal arm positions for twelve tasks; each block reverses on
the second repeat. Every assignment starts at the same per-repository frozen
commit in a fresh neutral worktree. B/C receive cold real production approval and
index setup; A has no Memglide state. Native state is fresh in every arm. Provider
and OS caches remain uncontrolled; observed cached input is reported separately.
Trusted fixture Git operations discard inherited Git configuration, disable
system/global hooks, filters and conversion attributes, and verify canonical
blob/path hashes and fresh-worktree bytes against retained upstream files. The
same installed TypeScript compiler is on every native PATH; its wrapper and
actual optional platform binary, Node/Git/Python binaries and runtime versions
are sealed. Upstream Git hooks and filters are not executed by fixture setup.

Source preparation occurs in a separate bounded Python child with a strictly
validated request. C's allowed keys are `arm`, `prompt`, `task_query`, `worktree`, `settings`;
only B may additionally receive `known_paths`. No private corpus/grader module is
imported by that child. The query is the exact nonempty public task substring,
bounded to 4,000 UTF-8 bytes. Common workflow instructions stay in native stdin
but cannot change automatic ranking relative to the offline public-task query.
The production launcher's strict v4 receipt validator checks its ABI and complete
coarse-selection diagnostics. Before native execution an independent verifier reconstructs
every selected complete file from frozen Git blobs and the exact canonical compact
envelope. It verifies ranges, hashes, byte accounting and the 12,000-byte cap.
The actual prepared stdin and native argv are retained and checked. Legitimate
passthrough remains a valid intent-to-treat observation, including negative cases.

Native exit zero, no timeout/interruption, complete error-free terminal supported
JSON framing/usage, zero MCP calls and a schema-valid final artifact are all
required. A second independent parser rejects duplicate/repeated thread lifecycle
framing, multiple cumulative turn totals and malformed usage. Native diagnostic
error/model-reroute items invalidate exact-model completion/pricing. All-zero or
zero-input/output counters cannot attest measured coding-response usage; raw
reported zeros remain in observed evidence and their cost is unknown.
The model's summary is never a grade. Protected original tests/Git
metadata and each task's protected manifest must be unchanged. A tracked patch,
Git status and untracked files are captured before independent grading. A separate
bounded Python/Node grader runs only the explicitly authorized coding fixture
logic, after agent execution, with its hidden test artifacts outside the agent
worktree. It must return an explicit success boolean and a positive executed-check
count. Baseline-fail/reference-pass controls establish a meaningful oracle.
Outside-worktree separation is procedural; it is not an OS read-access guarantee.

Public input is `--tasks`; `--grading` is keyed by task ID and requires
`known_paths` and `grader:{argv:[...],timeout_seconds:...}`. The structured argv
supports literal `{worktree}`, `{artifacts}`, `{task_id}` placeholders and is never
passed to a shell. Grader stdout is one JSON object with `success:bool`,
`checks:positive integer` and retained evidence. An optional `protected_manifest`
maps immutable relative paths to baseline SHA256. `--grader-root` contains all
private manifests, reference patches and grader code. `--fixtures` contains only
neutral source roots; `--provenance` follows the pinned upstream retained-tree
format used by the offline runner. The runner freezes the complete dedicated
private root, fixture tree, public/private inputs, source, helpers, protocol,
tests, pricing, native binary/version, prompt hashes, Git HEAD and settings.
The grader must use the sealed Python or Node interpreter, with an explicit
absolute script inside the frozen private root. Literal data paths stay in that
root. Before eligible native dispatch, each private task binds `task_digest` to
SHA256 of canonical public-task JSON and `fixture_hashes` to retained source.
Both `baseline_result` and `reference_result` require `executed:true`, positive
`checks`, that same `task_digest`, and `grader_script_sha256`; success must be
false for baseline and true for reference. These hash-bound receipts preserve
the independently authored execution evidence rather than using agent claims.

Before corpus selection, run `uv run python -m benchmarks.run_router_coding
--freeze-policy NEW_JSON`. This reads no corpus and writes the native source,
protocol, tests, complete benchmark-helper closure, configuration and actual
runtime/dependency seal. Planning/execution takes `--policy-freeze NEW_JSON` and
verifies it; eligible dispatch without the pre-corpus seal is forbidden. Root's
umbrella freeze also binds the independently reviewed offline policy seal.

Durable immutable attempt starts/results, atomic checkpoints, an exclusive study
lock and hash-chained event records are reused from the established harness. A
Linux supervisor records its exact private process identity and awaits the parent's
durable launch grant. It stays alive while native Codex executes; a parent-death
signal makes that supervisor SIGKILL its entire inherited private process group,
including native tools. Deliberately detached groups are outside this guarantee.
Every normal, timeout, error or interrupted exit cleans that private process group.
No automatic retry, auxiliary paid readiness call or supplemental assignment exists.
Resume validates frozen inputs, plan projection and sealed artifacts; interrupted
attempts remain unknown and never replace original observations. Finished resume
makes no new native launch.

At most 72 original assignment attempts may start; each native execution is at
most 180 seconds. The original separately labelled real preflight invocation is
retained in addition to those assignments. It failed at enforced HTTP CONNECT 403
with unknown usage and charge. No readiness request may repeat until a meaningful
supported network/runtime state change. Any future preflight is a new separately
counted invocation; native invocations are not inferred model-call counts. All
preflight history remains visible. A $20 API-price-equivalent soft admission
breaker includes known failed formal-attempt usage and the current successful
eligibility preflight tariff scenario. Before
each assignment it reserves the configured per-attempt estimate and checks a
bounded total wall-time budget. Missing whole-attempt usage, failed eligibility,
shared authentication/network/quota failures, interruption or harness/fidelity
failure stop further launches. A failed/unknown preflight produces explicit UNRUN
original slots without dispatch. The dollar breaker is not a provider-enforced
charge ceiling; native exposes no live billed-dollar cap. All attempted failures,
timeouts and interruptions stay in the numerator; unknown usage is null, never
zero. Every planned unrun slot retains its reason.

Usage comes from supported native events; model/API call counts and actual billing
remain null. Archived exact-model Standard rates verified on October 18 are a
separately named historical API tariff scenario. Fresh pricing access is blocked;
current applicability is unknown. A new verified price refresh, if available
before freezing a later run, can establish a more current scenario. Estimates
partition cache reads/writes within input,
reasoning already within output, short-context eligibility and possible-write
sensitivity. Missing cache-write usage leaves the point estimate null. Failed or
incomplete streams cannot become zero-cost runs. Estimated cost per success is
undefined when any formal attempted cost is unknown or no strict success exists.
Even if later formal attempts all have complete measured usage, the earlier
failed preflight's unknown usage leaves whole-study spending unknown. No estimate
establishes a whole-project $20 actual-charge ceiling.

Full execution timing includes cold B/C approval/index, process preparation and
native execution, excluding worktree creation, independent grading and reports.
Native launch time, parent setup CPU and sampled local child CPU/RSS are separate;
sampled CPU is a lower bound and RSS may double-count shared pages.
Waited child CPU around approval/index and local preparation is measured through
resource counters and included once. Preparation-interpreter startup CPU is not
covered; full execution wall time includes it. Filesystem-read
command proxies are not actual I/O counts. Whole-cohort intent-to-treat results,
status/measurement coverage and task-clustered paired descriptive differences are
reported. Language strata and source-delivery subsets cannot replace the primary
cohort. This small experiment cannot establish generality, invoiced savings or
automatic default promotion. A blocked native run supports no coding, token,
speed or cost-benefit claim.
