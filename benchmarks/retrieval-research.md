# Retrieval research and candidate experiments

Research date: **2026-10-16 UTC**. This document records primary online sources actually fetched during the retrieval investigation. These sources motivate experiments; they do not establish that Memglide improves coding success, token use, or cost.

## What the sources support

| Strategy | Primary source and observed behavior | Memglide experiment |
| --- | --- | --- |
| Preserve BM25 discrimination | [Apache Lucene `BM25Similarity.java`](https://raw.githubusercontent.com/apache/lucene/main/lucene/core/src/java/org/apache/lucene/search/similarities/BM25Similarity.java) uses term-frequency saturation, document-length normalization, and `log(1 + (N - n + 0.5) / (n + 0.5))` IDF. Defaults include `k1=1.2`, `b=0.75`. [SQLite's actual FTS5 BM25 implementation](https://raw.githubusercontent.com/sqlite/sqlite/master/ext/fts5/fts5_aux.c) uses `log((N - n + 0.5) / (n + 0.5))`, floors nonpositive IDF to `1e-6`, and returns the **negative** score so ascending SQL order is best first. | Compare the existing fixed FTS-hit bonus against meaningful ranking from FTS order or corpus-aware lexical evidence. Preserve the score sign. Test common words, rare identifiers, and long files; do not assume FTS scores have the same scale as hand-set identifier/path weights. |
| Normalize source identifiers and queries consistently | [Elasticsearch `word_delimiter_graph` documentation](https://raw.githubusercontent.com/elastic/elasticsearch/main/docs/reference/text-analysis/analysis-word-delimiter-graph-tokenfilter.md) demonstrates case splitting (`PowerShot` → `Power`, `Shot`), alphanumeric boundaries, optional original-token preservation, and warns that analysis choices affect matching and phrase positions. | Compare consistent camelCase, acronym, snake_case, path, and prose tokenization with baseline. Keep explicit whole identifiers and exact paths as strong evidence. Add singular/plural and stop-word behavior only with regression tests: these are local design choices, not claims from this source. |
| Fuse channels by rank when raw scores differ | [Elasticsearch RRF documentation](https://raw.githubusercontent.com/elastic/elasticsearch/main/docs/reference/elasticsearch/rest-apis/reciprocal-rank-fusion.md) defines `sum(1 / (k + rank))` across result lists, with a default rank constant of 60. [LangChain's implementation at the `langchain==0.3.27` tag](https://raw.githubusercontent.com/langchain-ai/langchain/langchain==0.3.27/libs/langchain/langchain/retrievers/ensemble.py) uses `weight / (rank + c)` and deduplicates document identities. | Compare weighted RRF over eligible identifier/path/full-text lists with a simpler lexical ranker. Keep exact-identifier intent and deterministic ties. Do not treat matching the same weak token in several channels as independent proof of relevance. Do not ship RRF merely because a source recommends it: retain it only if local retrieval tests improve. |
| Prefer relevant, distinct evidence | [LangChain's MMR implementation](https://raw.githubusercontent.com/langchain-ai/langchain/master/libs/core/langchain_core/vectorstores/utils.py) starts with the closest query result, then maximizes `lambda * query_similarity - (1 - lambda) * maximum_similarity_to_selected`. It defaults to `lambda=0.5`. | Test lightweight file/span diversity and duplicate suppression before adding embedding infrastructure. Multiple declarations from one file can consume a small context budget without adding new evidence. File/span diversity is inspired by the redundancy tradeoff; it is **not embedding MMR** and should be named accurately. |
| Separate candidate retrieval from final ranking | [Sentence Transformers' retrieve-and-rerank guide](https://raw.githubusercontent.com/UKPLab/sentence-transformers/master/examples/sentence_transformer/applications/retrieve_rerank/README.md) retrieves a larger candidate pool and then reranks it. It explains that lexical search misses synonyms, while cross-encoders score query/document pairs jointly but cost more per candidate. | Test deterministic candidate reranking and source selection first. Embeddings or a cross-encoder are a possible later experiment, requiring a pinned model and measured quality, latency, CPU, and memory. No semantic model was downloaded or evaluated as part of this research. |

## Failure mechanism to test locally

The initial `Indexer.search` inspection found that every FTS hit received `full_text + min(-bm25, full_text)`, with a default fixed component of 10. For common terms, SQLite's IDF floor can produce very small positive values after negating its result. Consequently, many distinct hits receive almost the same bonus of 10. This is a concrete reason to compare rank-aware scoring; it does not imply that all BM25 scores are small, or that RRF will automatically win.

The initial context inspection also showed that direct candidates, dependencies, related tests, metadata, and warnings share one token budget. A retrieval result can be ranked correctly yet fail to include the relevant source after packing. The locally motivated candidate is to fit direct source evidence first, avoid duplicate source spans, and cap or omit graph metadata before evicting those sources. This source-before-graph policy is an implementation hypothesis, **not a result established by the external references**. Context budgets, freshness warnings, and full-file behavior still need their own tests.

## Experimental decision rules

Compare changes against the saved baseline using the same task prompts, fixture repositories, context levels, and budgets. Keep all misses. The 24 coding fixtures provide expected-target-file labels, so their coverage is a reference-coverage proxy rather than proof that every piece of necessary context was retrieved. Report top-1 target-file accuracy, reciprocal rank, coverage within the returned context, context size, and retrieval latency where measured. Add separate adversarial cases for no-match queries, generic nouns that coincide with class names, partial identifier collisions, exact identifiers, exact paths, caller queries, unrelated graph neighborhoods, and repeated declarations from one file.

Use an ablation for each accepted mechanism rather than inferring causality from one combined patch. The evaluation report must distinguish experiments actually run from these proposed candidates. Prefer the simplest tested implementation that improves reference coverage without breaking exact lookups, caller retrieval, project isolation, or context freshness. Model token usage, actual billing, and task success still require the separate paired Codex A/B benchmark.
