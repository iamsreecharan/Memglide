# Initial workflow study: test-protection contract failure

The initial frozen study completed all **60 native assignments**, with valid native execution and source treatment. Every external behavioral, smoke and TypeScript compilation command exited successfully. Nevertheless, **all 60 assignments remain failed** under the original byte-protection rule. Cost per successful task is therefore unavailable.

The task asked agents to “add regression tests if useful” and “preserve public interfaces and all existing tests.” The grader required existing test files to remain byte-identical. Agents changed those existing files, often by appending regression cases. That normal coding interpretation conflicts with the unstated byte-level constraint. The original protected-file checks correctly rejected the changed bytes; they will not be weakened after seeing results.

All dollars are API list-price equivalents from observed usage, not actual charges. These failures and their spend remain part of the final evidence and campaign accounting. Passing external behavior alone does not retrospectively make these successful assignments.

The prespecified support promotion gate also fails focused cost and latency checks independently of the correctness failure. Support remains optional. No favorable behavior-only regrading replaces the original results.

The correction is a new versioned benchmark with ten fresh Python/TypeScript tasks and explicit instructions: **keep original tracked test files byte-identical; put any regressions in new files**. Strict protected-byte grading, matched native settings, both repeats and the existing promotion policy remain. The new study is a confirmation after a protocol defect, not a rewrite of this experiment. Different task corpora will stay separate; an additional campaign view includes every attempted dollar and strict success.
