This supplement records the twelve prospective task contracts, pinned public inputs, original public-check counts, allocation and
measurement protocol, source revisions, and reproducibility boundaries for the installed Memglide ablation. It also retains twenty-three
historical study stages and all thirty adaptive development rounds, including rejected candidates and failed attempts. Native coding
outcomes are reported in the accompanying paper; historical cohorts and local controls are kept separate.

1     Scope and reading guide
The accompanying paper studies repository-context preparation around the installed Codex coding agent. This supple-
ment makes the task contracts and measurement lineage readable without treating every development observation
as independent confirmation. Its public-library feature tasks differ from the historical GitHub issues evaluated by
SWE-bench [1]. The underlying model weights were not trained or changed for this work.
    Identifiers p01–p06 refer to the Python lane; t01–t06 refer to the JavaScript/TypeScript lane. Repository IDs pr01–
pr06 and r07–r12 are local provenance identifiers, not experimental outcomes. “Native session” means a coding-agent
evaluation through codex exec. Source preparation, SDK calls, zero-model handoffs, local component tests and codex
sandbox grader processes are different forms of evidence. Their counts must not be added to native session counts.
Internal provider inference counts and account billing are unavailable.
    All monetary figures below are observed-token tariff equivalents under the stated accounting convention. Missing
usage remains unknown. A failed attempt retains its cost when usage is known. Reused-task repairs, post-hoc subsets
and alternate tariffs remain labeled. The history inventory records 66 matching report/research files, including two
archived duplicates; this inventory is a report review rather than an independent replay of every historical stream.

2.2   Public command conventions
The exact atomic argument vectors, environment updates, expected positive test counts and timeouts are in the frozen
per-lane task/command JSON files. The short forms below are a readable transcription, not new commands substituted
for those vectors. {root} denotes the fresh assignment repository.
    Python commands use the pinned Python executable to run pytest with -q -c /dev/null --rootdir {root} -p
no:cacheprovider. They set PYTHONDONTWRITEBYTECODE=1, PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 and
an explicit PYTHONPATH containing the isolated extensions, {root}/src and {root}. Each Python atomic public
command has a 45-second limit. Benchmark smoke commands also load pytest_benchmark.plugin explicitly and use
--benchmark-disable.
    The two Mocha commands use --reporter dot test/. AVA commands use --tap --serial --config with
the frozen external no-cache configuration. Declaration commands use tsd with --typings index.d.ts --files
index.test-d.ts; the strip-final-newline command explicitly selects its compatible tsd-legacy 0.31.0 entry point. Other
declaration commands retain their frozen executable binding. JavaScript/TypeScript public commands have 60-second
limits.
    Every feature prompt below is reproduced verbatim. The common developer contract additionally requires production-
only edits, relevant public and new regression checks, preservation of existing behavior, and exact protection of all
existing tests, snapshots, configurations, manifests, lockfiles, documentation, license files and Git metadata. New
regression-test files are allowed. Network use, package installation, Git staging/commits and reading outside the
repository except declared tools/profile are prohibited. Every shell sources the same declared profile. The final structured
response reports a concise change summary and commands actually run; it does not supply a grade or usage claim.

3     Frozen installed-system protocol
3.1    Conditions and expected activation
A is the installed launcher in explicit off/pass-through mode. B enables v4 source discovery and compact complete
selected source. C uses the same source policy and adds the locked public-command/baseline-count card from a fresh,
explicitly verified receipt. The intervention changes context preparation around the same coding model. The two
primary contrasts are C minus A and C minus B.
    Zero-model installed readiness fixes the expected treatment for every task. p01–p05, t05 and t06 preload source. p06
and t01–t04 preserve the exact task because candidates are ambiguous. These seven active and five abstaining tasks
Memglide: Bounded Repository Context                                                                                   7


define descriptive readiness strata. All twelve remain in the primary intention-to-treat panel, including preparation
overhead on abstentions. There are no subgroup hypothesis tests, and the active subset cannot replace the primary
panel.
  The same short feature request enters each launcher. Common safety/tool instructions use native developer_instru
ctions, and project_doc_max_bytes=0 disables uncontrolled project-document injection in all arms. Added context
changes the actual native prompt only as assigned. Thirty-six zero-model installed handoffs establish treatment before
freeze. The bridge records actual native prompt bytes and arguments, validates their bindings, and executes the installed
Codex once in the same process. The first scheduled assignment also serves as connectivity verification; no additional
paid smoke session is added.

3.2   Allocation and stopping
One task in each repository receives three arms and two repeats, giving 72 scheduled workflows and 24 cells per arm.
Seed 20261027 shuffles tasks and a multiset containing every arm permutation twice. The first-repeat order is:

  Repeat two reverses the complete first-repeat assignment sequence, including both task-block order and within-task
arm order. Assignments execute sequentially. Each receives a fresh source copy, Git baseline, local project state and
native thread. This balances order under the saved design but cannot eliminate filesystem or provider-cache carryover.
  An assignment is durably allocated once. There are no native retries, replacements or outcome-driven extra repeats.
The next-unused-assignment controller stops on unknown whole-attempt usage, native lifecycle failure, integrity
failure or exhausted admission allowance. Unrun cells remain unavailable. The planned maximum is 72 coding-agent
dispatches, with a soft USD 18 allowance in uniform tariff equivalents and a USD 0.25 next-call reserve. Neither value
bounds account billing or an admitted call’s cost.

3.3   Time boundaries and caches
Public-source copying and Git-baseline construction are excluded from all workflow timers. Timing starts before
arm-specific registration, indexing or verification, and ends after native process-group cleanup. C includes public

baseline verification and removal of only newly generated logs, build outputs and caches. Source/Git bytes and the
provider manifest are checked afterward. This cleanup is an experimental control, not automatic shipping behavior.
Indexing, verification, cleanup, launcher preparation and native intervals are recorded separately.
    A shared absolute 90-second allowance covers setup through launcher preparation; it is not 90 seconds for each
component. Every native process has a separate 300-second allowance beginning at the recorded bridge handoff. Native

operating-system page caches, provider prefix caches, cloud load and model-backend revisions remain uncontrolled.
Reported cached input is retained rather than attributed to a particular causal source.

3.4   Author controls, private inputs and grading
Separate AI authoring roles proposed tasks and constructed reference, baseline and plausibly incorrect variants; an
additional agent reviewed agreement and records. This is automated role separation, not independent human replication.
Across twelve tasks there are 36 expected control outcomes: baseline fails the feature, reference passes, and the incorrect
variant fails while original public tests remain unchanged. Feature, public and declaration checks are finite and cannot
establish exhaustive correctness.
    Before native collection, all new private grader/reference/control plaintext, compiled copies and revealing logs were
removed from the executor. The 3,151 committed files were packed, encrypted and authenticated with AES-GCM. A
random 256-bit key remained only in the external orchestrator store. Ciphertext and hash commitments could remain
locally; every private plaintext root had to be absent before each dispatch. This sequesters these oracles without claiming
kernel-level isolation from arbitrary local data. Restoration occurs only after all native timings close or a durable stop,
and exact committed file hashes must match before restored graders execute.
    Before grading native patches, all 36 original author variants were replayed successfully through the same final
frozen sandbox wrapper. TypeScript control-helper working-directory/module-ancestry diagnostics were retained; only
the location of that unsealed control helper was corrected to the actual grading ancestor. The frozen private cases,
feature oracles, original public checks and runtime were unchanged. These control processes made no model requests.
The final wrapper had been tightened before freeze; there was no post-freeze study/grading amendment.
    Independent feature and original-public grading use candidate source read-only, network disabled and only grader
artifacts writable. Inherited global temporary write roots are disabled. Candidate and protected-input hashes are
checked before and after grading. The strict gate requires valid native completion and whole-attempt usage, faithful
treatment, intact protected inputs, valid grading infrastructure, committed feature checks and original public checks.
Regression-test presence and execution remain diagnostics. A passing rubric cannot certify semantic test quality, full
free-form instruction compliance or the unobservable base58 allocation order.

3.5   Accounting and inference
The primary accounting convention is [(input − cached input) × 5 + cached input × 0.20 + output × 15] / 1,000,000, in
API-equivalent dollars. Cached input is part of total input; reasoning output is included in output counters. These fixed
historical rates do not represent current prices, invoices, subscription charges or all provider computation. Ordinary
failed attempts retain observed costs. Unknown usage is never replaced with zero.
Memglide: Bounded Repository Context                                                                                   9


    For each primary contrast, both repeats are averaged within each task before forming the paired arm difference. A
complete estimate requires all twelve task clusters and both repeated costs for both contrasted arms. Otherwise the
primary total, effect and test are unavailable; known subtotals and missing identifiers remain reportable. The primary
family is the two contrasts C–A and C–B, not a collection selected after results.
    Complete contrasts receive pointwise 95% paired task-bootstrap intervals using 10,000 resamples, seed 20261029 and
linear interpolation at (n−1)p. Each draw retains repeats and paired arms. Exact two-sided tests condition on the third
arm’s first-repeat position, creating three strata of four tasks with two relative orders each. Enumerating choose(4,2)ˆ3
= 216 legal allocations and jointly swapping repeat labels respects the balanced design. Ties count. Pairwise sharp-null
and no-cross-arm/provider-cache-carryover assumptions are required. Holm adjustment covers the two predeclared
cost tests at familywise 0.05; missingness does not shrink that family.
    Native-price/cache-write sensitivities, tokens, workflow components, readiness strata and joint-success time are
secondary descriptive analyses. Command-text read/test counts are heuristic and do not trace all file I/O or provider
inferences. Cheaper failed work is not evidence of greater efficiency. Matching strict-success counts does not establish
population quality equivalence or formal noninferiority.
    Precision planning used seven earlier complete two-repeat task clusters. Their unstable cost-difference standard
deviation was 0.03441 dollars. An optimistic normal approximation suggests a detectable difference near 0.03063 dollars,
roughly 25% of the earlier A mean, for twelve clusters at 80% power and first-step two-sided alpha 0.025. This is
not achieved power or a guarantee for the exact test. Adaptive prototype observations are not pooled with this new
installed-system panel.

5     The thirty-round v5 development search
5.1    Rules and interpretation
The v5 development screen used three fixed tasks, three initial reference sessions and 30 candidates with one native
session per task. Each candidate was frozen before its round. Ninety candidate sessions plus three references give
93 development sessions. Reference and candidate rounds used the same three-worker submission policy; recorded
submission order did not guarantee native start order. Cached provider state and concurrent contention remained
uncontrolled. Final v5 evaluation ran sequentially after the winner lock.
     Candidate changes were portable prompt/preparation/workflow changes. They did not retrain the coding model.
The candidate had to preserve task text and source provenance and could not encode task IDs, private expectations or
reference solutions. A candidate branched from the current incumbent; rejected versions and their measurements were
retained rather than destructively reset.
     Promotion first required valid complete native/treatment/usage records and no protected-input or infrastructure
failure. A candidate could not lose a task passed by its incumbent. Before the incumbent reached 3/3, promotion required
strict pass-vector dominance. At 3/3, a candidate had to keep 3/3 and improve aggregate cost or time by at least 5%,
while the counterpart worsened by at most 5%. Each task passed by both versions also had to remain within 130% of its
incumbent cost and time. Exact thresholds were admitted; ties kept the incumbent. These fixed engineering screens
over three observations were not significance tests. Thirty adaptive looks create selection bias and winner’s-curse risk.
     The entries below reproduce each saved hypothesis, effective configuration change, strict outcome, both tariff
conventions, summed preparation-plus-native time, parent and recorded decision. Every aggregate includes all three
attempts, including failures. Times are sums of the three preparation/native components, not the wall-clock duration of
a parallel round. Promotion used the separately retained frozen controller timing measure. The original strict grader is
unchanged; the later compiler-alignment diagnostic does not rescore these primary rounds.

and analysis rules. Replay begins by verifying manifest hashes and separating historical snapshots from the new

rebinding and fresh verification, not a claim of byte-identical frozen execution.
    Analysis and grading of retained outputs do not require new coding-model requests. A new native replication
requires its own authenticated supported Codex connection, the declared runtime/profile and a new prospectively
frozen schedule/state. It must not overwrite original slots or treat provider, backend, account or cache differences as
controlled. Credentials and account configuration are not scientific evidence and are not distributed.
    The controller exposes separate prepare-public, preflight, seal, verify, run and grade phases. Public prepara-
tion combines task/protection metadata; readiness uses a separate zero-model executable; sealing binds inputs; verify
checks that commitment. run allocates only unused assignments and honors stopping rules. grade requires native

the outer launcher’s original stdin. The final analysis keeps unavailable cells explicit and applies the predeclared paired
design.
